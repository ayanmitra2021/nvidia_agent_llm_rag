How these counts work

Each record represents a cache match, a shared-response match, or an upstream HTTP attempt. Retries and fallback can produce multiple attempts for one learner request. The fallback endpoint category uses the currently configured address; it does not prove a request used fallback routing. Other endpoints can include previous configurations. Model discovery is excluded. Requests rejected before cache or provider dispatch may have no journal record.

Cache hits are recorded before playback. HTTP status is recorded when response headers arrive; HTTP 200 does not confirm a completed stream. Unconfirmed records may be pending, interrupted, or abandoned. Jaeger provides timing and completion details where tracing is instrumented.

Model labels use known public names and configured public aliases. Unmapped historical identifiers are shown as “Other / unavailable model.”
